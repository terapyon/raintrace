# Spec 04: 降雨と UI の統合

- Status: Draft（レビュー待ち）
- 日付: 2026-09-10
- 対応: base-spec §10〜§12、§33〜§39、§55 Phase 4、§57 #5・#11・#12、§58、§59
- 依存: 02、03
- 後続: 05、06

---

## 1. 目的

03 のエンジンを Worker に載せ、02 の画面につなぎ、降雨の設定から再生・統計・セル情報までを一通り操作できるようにする。

この spec が終わると、base-spec §57 の PoC 完成条件のうち、3D 表示（#4・#9）以外のすべてを 2D で確かめられる。

## 2. スコープ

### 含む

- Worker の再生ループと、メッセージの定義（`shared/protocol.ts` の拡張）
- 水深バッファのダブルバッファ転送（tech-spec §5.2）
- 設定とシミュレーション状態のストア（Zustand）
- UI: `RainfallControls`、`PlaybackControls`、`StatisticsPanel`、`CellInfoPopover`、`DisplaySettings`、範囲の大きさの選択（250・500・1000m）
- 水深の 2D 表示と、水の流れの矢印
- 平衡での自動停止、越流イベントの通知
- 設定の保存（localStorage。tech-spec §8.3）と URL（`mm`・`r`・`size`）
- 免責表示（tech-spec §9.6）
- ベースマップ（標準・淡色・写真）とテーマ（light・dark・system）の切り替え
- tech-spec §11.4 の E2E スモークテスト一式

### 含まない

- 3D（05）、降雨時間（R04-3）、複数の降雨地点（base-spec §53.1）

## 3. 操作の流れ

```
1. 地点をクリック（02）   → 範囲の DEM を読み込み、中心に降雨マーカー
2. 雨量・半径を指定      → 既定は 100mm・10m（base-spec §10）
3. Start                → 雨を置いて再生を始める
```

| 操作 | 挙動 |
|---|---|
| Start | 雨を置き（`addRainfall`）、再生を始める |
| Pause／Resume | 一時停止と再開 |
| Step | 一時停止中に 1 step 進める |
| Reset | 水を消して step 0 に戻る。地形はそのまま |
| 雨量・半径の変更 | 未開始なら自由に変えられる。開始後は Reset するまで入力できない |
| 地点・範囲の大きさの変更 | DEM を読み込み直し、リセットする（base-spec §36） |

base-spec §58 の「3 操作以内」は、初回の免責の了解を除いて数える（R04-4）。

## 4. 地図クリックの意味（R04-1）

| 状態 | クリックした場所 | 挙動 |
|---|---|---|
| 地点が未選択 | どこでも | そこを地点にする（範囲を読み込む） |
| 地点を選択済み | 範囲の中 | `CellInfoPopover` を開く（標高・水深・水位を 0.01m 単位で。無効セルなら「標高データなし」）。中に「ここを降雨中心にする」ボタン |
| 地点を選択済み | 範囲の外 | 小さなポップオーバーに「ここを新しい地点にする」ボタン |

- 降雨マーカーはドラッグで動かせ、離した位置が新しい地点になる
- 範囲は降雨中心を中心とする（R04-2）。降雨中心を変えると、範囲の DEM を読み込み直してリセットする
- 状態の遷移は純粋な関数（reducer）として書き、ユニットテストする

## 5. Worker とメッセージ

### 5.1 メッセージ（`shared/protocol.ts`）

| 方向 | メッセージ | 内容 |
|---|---|---|
| メイン → Worker | `loadArea` | 02 で定義済み |
| | `start` | `{ rain: RainfallInput }`。雨を置いて再生 |
| | `pause`・`resume`・`step`・`reset` | |
| | `setSpeed` | `{ speed: 0.25 \| 0.5 \| 1 \| 2 \| 4 \| 'max' }`（`'max'` は「最速」） |
| | `setArrowSpacing` | `{ spacingM: 5 \| 10 \| 20 }` |
| | `returnBuffer` | `{ buffer: ArrayBuffer }`（Transferable） |
| Worker → メイン | `areaLoaded`・`loadProgress`・`loadError` | 02 で定義済み |
| | `frame` | `{ step, water: ArrayBuffer（Transferable、Float32 × N²）, arrows: Float32Array, stats: StepStats }` |
| | `error` | `{ message }` |

`arrows` は、`flowVectors()` を Worker 内で `spacingM` ごとに間引き、流れのある地点だけを `[x, y, 角度, 大きさ]` の並びにしたもの。水深全体ではなく間引いた結果だけを送るので、転送量は小さい。矢印が表示されていて、かつ frame を送る tick でだけ計算する（03 §3.9）。矢印が非表示なら空の配列を送る。

### 5.2 再生ループ（R04-5）

- Worker は毎秒 60 回を目安に tick を回す。1 tick には時間予算（12ms）を設け、その中で回せるだけ step を回す。予算を残して tick を終えるので、`pause` や `returnBuffer` などのメッセージを処理する機会が保たれる
- 速度は、1 tick あたりの step 数の上限として効く。1x は毎秒 60 step（1 tick に 1 step）、0.25x は 4 tick に 1 step、4x は 1 tick に 4 step とする（端数は次の tick へ繰り越す）。**「最速」は上限を持たず、時間予算だけで回す。** 大きな池が平らになるまでの待ち時間（03 §4.1）に対する、最も安価な緩和策である
- 計算が予算に収まらない場合、実際の step 数は上限を下回る。実際の毎秒の step 数を統計に出す
- tick の終わりに、メイン側から返却済みのバッファがあれば、水深を単精度で書き写して `frame` を送る。無ければそのフレームは送らない（tech-spec §5.2）
- `StepStats.settled` が true になったら自動で一時停止する。平衡を知らせる専用のメッセージは設けず、`frame` の統計で伝える（自動停止した時点のフレームは、バッファが返却され次第必ず送る）。画面には「平衡に達しました（Step N）」と出す
- 再生ループは、スケジューラの部分を純粋なクラスに切り出し、偽のタイマーでテストする

### 5.3 メインスレッドの受け取り

- `bridge/SimulationClient` が `frame` を受け取ったら、手元の古いバッファを `returnBuffer` で返し、新しいバッファを手元に置く。手元のバッファは、次のフレームまでセル情報の読み取りに使う
- 統計は 10Hz に間引いてストアへ入れる（tech-spec §5.1）
- 越流イベントは、MUI の `Snackbar` で「窪地（spill 標高 12.70m）から越流が始まりました（Step N）」と通知し、パネルの一覧にも残す（base-spec §21）

## 6. 表示

### 6.1 水深の 2D 表示（R04-7）

- 02 と同じく、範囲の四隅に合わせた `canvas` ソースで表示する。毎フレーム内容が変わるので `animate: true` とする
- 描画フレームごとに、最新の水深バッファから RGBA を作る。1cm 未満は透明（base-spec §30）
- 配色は、色覚特性に配慮した青系の連続色。段階表示では 5cm 刻みで 1m まで 20 段、1m 以上は 1 色（tech-spec §6.6）。連続表示も選べる
- 凡例を出す
- 着色はメインスレッドで行う（262,144 セルで 2〜4ms の見込み）。複数のフレームが届いても、描くのは最新の1つだけにする。GPU での着色は 05・06 で検討する

### 6.2 水の流れの矢印

- `arrows` を GeoJSON の点にし、symbol レイヤーで回転した矢印を表示する（base-spec §32）
- 更新は 10Hz に間引く
- 02 の「地形の流向」とは別のレイヤーとし、パネルでは「水の流れ」「地形の流向」を別々に切り替える

### 6.3 統計（base-spec §38）

| 項目 | 表示 |
|---|---|
| Step | `Step 1234` |
| 投入水量 | m³、小数 1 桁（1m³ 未満は小数 2 桁） |
| 領域内の水量 | 同上 |
| 領域外流出量 | 同上 |
| 最大水深 | m、0.01m 単位 |
| 湛水面積 | m²（水深 1cm 以上のセル） |
| 実行速度 | step／秒 |

base-spec §33 のとおり、実時間との対応を示す表現（「10 秒後」など）は使わない。

## 7. 設定と URL

- `settingsStore` は Zustand の `persist` ミドルウェア（Zustand に同梱。依存は増えない）で localStorage に保存する。キーと形は tech-spec §8.3 のとおり
- 読み込み時に型と範囲を検証し、不正な値や `schemaVersion` の不一致があれば既定値に戻す（tech-spec §8.3）。検証は型ガード関数を手で書き、検証ライブラリは入れない
- URL の `lat`・`lon`・`z`・`size`・`mm`・`r` を読み書きする。URL と localStorage の両方にある項目は URL を優先する（tech-spec §3.3）。書き込みは `history.replaceState` で、変更から一定時間を置いてまとめて行う

## 8. 免責表示（base-spec §59、tech-spec §9.6）

- 初回の起動時に `DisclaimerDialog`（モーダル）を出し、「了解しました」を押してもらう。押した日時を `disclaimerAcknowledgedAt` に保存する
- 了解後も、パネルの下端に短い注意文を常に表示し、全文へのリンクを付ける
- どちらも設定で消せない

## 9. 入力の検証（R04-6）

| 項目 | 範囲 | 既定 |
|---|---|---|
| 雨量 | 1〜1000mm（整数） | 100 |
| 半径 | 1m〜範囲の一辺の半分 | 10 |
| 範囲の大きさ | 250・500・1000m | 500 |

範囲外の値は入力欄にエラーを出し、Start を押せなくする。

## 10. エラー処理

| 事象 | 挙動 |
|---|---|
| 降雨中心が無効セル | 03 のエラーを「降雨中心に標高データがありません」として表示 |
| Worker の異常終了 | エラーを表示し、「再読み込み」で Worker を起動し直して範囲を読み込み直す |
| localStorage が使えない（プライベートモードなど） | 保存せずに動作を続ける |

## 11. テスト

### 11.1 ユニット（UI のテストのため jsdom と Testing Library を追加する。理由を PR に記す）

| 対象 | 内容 |
|---|---|
| 設定の検証 | 不正な値・古い `schemaVersion` で既定値に戻る |
| URL の優先順位 | URL と localStorage が食い違うと URL が勝つ |
| クリックの状態遷移 | §4 の表のすべての遷移 |
| 入力の検証 | 範囲の境界値で Start の可否が切り替わる |
| 数値の書式 | 0.01m 単位、m³ の桁 |
| 配色 | 水深から 5cm 刻みの色への対応、1cm 未満が透明 |
| 再生のスケジューラ | 速度ごとの step 数、端数の繰り越し、時間予算での打ち切り、「最速」、バッファが無いときのフレームの見送り、平衡での自動停止 |

### 11.2 E2E（tech-spec §11.4）

1. アプリが起動し、地図タイルが読み込まれる
2. 地図をクリックすると、降雨マーカーが表示される
3. DEM 情報バッジに使った DEM が出る
4. 既定の設定（100mm・10m）で Start を押すと、投入水量が「31.4 m³」になり、Step が進む
5. Reset で、投入水量が 0 に、Step が 0 に戻る
6. 免責ダイアログが初回だけ表示される
7. `?mm=50&r=20` を付けて開くと、入力欄にその値が入っている
8. 範囲内をクリックするとセル情報が開き、「ここを降雨中心にする」で範囲が読み込み直される
9. キーボードだけで、雨量・半径の入力から Start・Pause・Reset まで操作できる（tech-spec §9.5）

### 11.3 手動確認

02 と同じ 3 地点（R02-7）で降雨を実行し、水が溜まる場所が 02 の窪地表示と整合するかを確かめて、スクリーンショットを PR に記録する。

## 13. 裁定が必要な論点

| ID | 論点 | 推奨 | 理由 |
|---|---|---|---|
| R04-1 | 地図クリックの意味 | §4 のとおり（レビュー役の案を採る） | base-spec §36 と §39 の衝突を、モードの切り替えなしで解消できる。3 操作の目標も保てる |
| R04-2 | 範囲と降雨中心の関係 | 範囲は降雨中心を中心とする。中心を動かすと読み込み直す | base-spec §8・§36 と tech-spec §3.3 の URL の定義に沿う。範囲と降雨中心を切り離すと、URL の形と操作が複雑になる。複数の降雨地点（base-spec §53.1）を入れるときに見直す |
| R04-3 | 降雨時間 | PoC では瞬時の投入のみ | base-spec §55 の Phase 4 は「降雨時間」を含むが、§12 は Version 0.1 を瞬時の均一降雨とし、§53.2 は時間雨量を将来の機能としている。さらに §33 のとおり step は実時間と対応しないので、「30 分間」のような時間を定義できない。base-spec §55 との差異になる |
| R04-4 | 3 操作の数え方 | 初回の免責の了解を除く | 免責は一度きりで、以後の操作回数には影響しない |
| R04-5 | 再生速度と自動停止 | §5.2 のとおり（時間予算の中で回し、速度は step 数の上限。「最速」を加える） | base-spec §34 の速度の候補に合わせ、大きな池の平衡を待つための「最速」を加える（03 §4.1）。1 tick に時間予算を設けるのは、計算が重いときにもメッセージを処理できるようにするため。平衡のあとも再生を続けても何も変わらないので、自動で止める |
| R04-6 | 入力の範囲 | §9 のとおり | 雨量の上限 1000mm は、日本で観測された日降水量の最大級の値を上回るよう、余裕を持たせて置いた。半径の上限は、雨が範囲の外にはみ出さないため |
| R04-7 | 水深の 2D 表示の方式 | メインスレッドの canvas で着色 | 最も単純で、2D の検証には十分な速さの見込み。tech-spec §14.1 のメインスレッドの最長ブロック 50ms も満たせる。足りなければ 05・06 で GPU に移す |
