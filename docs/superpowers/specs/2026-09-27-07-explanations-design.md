# Spec 07: 地図の印の説明と、流出の説明・可視化

- Status: 草案（2026-09-27）
- 日付: 2026-09-27
- 対応: base-spec §18（境界条件）・§30（描画閾値）・§38（統計）・§59（免責）
- 依存: 02、04、05
- 後続: 08（物理時間の降雨）

---

## 1. 目的

v0.2.0 のデモで、ユーザーから次の 2 つの疑問が出た（2026-09-27）。この spec はそれに答える。

1. 地図に出る ○ が何を意味するのか分からない。
2. シミュレーションを続けると水が無くなる。排水を考えているのか。

調べて分かったこと:

- ○ は `terrain-markers` 層（`src/map/TerrainOverlay.ts:171-188`）で、2 種類ある。
  - **青は最低点**。範囲の中で標高が最も低い有効セル（`lowestCell()`）。
  - **オレンジはあふれ出し点**。有意な窪地（最大深さ 0.1 m 以上、面積 10 m² 以上）ごとの spill セル。満水になると、ここから水があふれ出す。
  - UI には説明も凡例もなく、クリックしても何も起きない（クリックは範囲の中のセル情報として扱われる）。
- エンジンには下水・浸透・蒸発の項は無い（base-spec §3 の対象外）。水が減る経路は 1 つだけで、範囲の端と、無効セル（海・データ欠損）への流出である（`src/simulation/FlowSolver.ts:134-150`、base-spec §18、tech-spec §6.6）。流出した量は統計の「領域外流出量」に出ており、投入水量 = 領域内の水量 + 領域外流出量 が成り立つ。
- さらに、1 cm 未満の水は描かない（`WATER_VISIBLE_M`、base-spec §30）。そのため、薄く広がった水は領域内に残っていても見かけ上消える。

ユーザーの裁定（2026-09-27）:

- ○ をクリックすると、説明と数値をポップアップで出す。凡例にも 2 色を足す。
- 水が減る理由を画面で説明する。流出している縁を地図上で見せる。
- 物理時間の降雨は別の spec（08）で扱う。

## 2. スコープ

### 含む

- ○ のクリックで開く説明のポップオーバー（`MarkerInfoPopover`）と、○ の上でのカーソル
- ○ の凡例（最低点・あふれ出し点）
- 「領域外流出量」の説明（ツールチップ）と、水深の凡例への 1 cm の注記
- 注意事項の文の追記
- 流出しているセルの地図上の表示（2D・3D）と、その表示の切り替え

### 含まない

- エンジンの計算の変更（流出の扱い・排水の項）。排水は 08 以降で検討する
- 範囲の端を壁にする設定（ユーザーは今回選んでいない）
- 物理時間・降雨時間（08）

## 3. ○ の説明ポップオーバー

### 3.1 クリックの判定

`terrainSession` の `onClick`（`src/ui/terrainSession.ts:74-88`）で、`clickTarget` を求める前に `map.queryRenderedFeatures(event.point, { layers: [TERRAIN_LAYER_IDS.markers] })` を呼ぶ。1 つでも当たれば、セル情報の代わりに印の説明を開く。

- 当たりの判定は、描画された円（半径 6 px、白い縁 2 px）に任せる。指で押しやすくするため、`queryRenderedFeatures` には点ではなく ±4 px の矩形を渡す。
- 最低点とあふれ出し点が重なったときは、最低点を優先する（R07-4）。
- 3D でも ○ は出ている（`src/map/view3d/*` はこの層に触れない）。3D の中のクリックでも同じように開く。

### 3.2 状態

`src/state/clickState.ts` の `Popover` に次を足す。

```ts
| { kind: 'marker'; marker: 'lowest' } & Anchor
| { kind: 'marker'; marker: 'spill'; depressionId: number } & Anchor
```

`Anchor` は既存の `lon`・`lat`・`x`・`y` とする。`ClickEvent` には `{ type: 'marker-click'; … }` を足し、純粋関数 `reduceClick` で扱う。

- 「ここを降雨中心にする」の `confirm` は、印のポップオーバーでは出さない。
- `marker-drag-end` と `close` の扱いは既存と同じ。

### 3.3 地物のプロパティ

`markerFeatures()`（`src/map/terrainFeatures.ts:59-73`）のプロパティに、あふれ出し点だけ `depressionId`（`Depression.id`）を足す。数値はクリックのときに `appStore` の `terrain.depressions` から引く。

### 3.4 表示（`MarkerInfoPopover`）

形は `CellInfoPopover` と同じにする。MUI `Popover` を `anchorReference="anchorPosition"`、`hideBackdrop`、`disableScrollLock`、`disableEnforceFocus` で置き、root の `pointerEvents: 'none'` と paper の `'auto'` も揃える。

| 印 | 見出し | 説明 | 数値 |
|---|---|---|---|
| 最低点 | 最低点 | 範囲の中でいちばん低い地点です。水が集まりやすい場所の目安です。 | 標高 |
| あふれ出し点 | あふれ出し点 | くぼ地が水で満たされると、ここから水があふれ出します。 | あふれる標高（`spillElevation`）、くぼ地の最大の深さ（`maxDepthM`）、ためられる水の量（`capacityM3`）、くぼ地の面積（`areaM2`） |

- 数値の書式は `src/ui/format.ts` の既存の関数を使う（`formatMeters`、`formatVolume`、`formatArea`）。
- 「閉じる」ボタンを置く。
- 文言はすべて `src/ui/strings.ts` の新しい `markerInfo` に置く。

### 3.5 カーソル

`map.on('mouseenter', markers, …)` と `mouseleave` で、○ の上では `cursor: pointer` にする。地図のドラッグ中のカーソルは MapLibre に任せる。

### 3.6 凡例

`DisplaySettings` の凡例群に `MarkerLegend` を足す。色は `TerrainOverlay` の定数と同じ値を、1 つの場所から import する（色を二重に持たない）。

- ● 最低点（#1565c0）
- ● あふれ出し点（#ef6c00）

## 4. 水が減る理由の説明

### 4.1 統計の「領域外流出量」

`StatisticsPanel` の「領域外流出量」の横に情報アイコン（`InfoOutlined`、small）を置き、MUI `Tooltip` を付ける。キーボードでフォーカスでき、タップでも開くようにする（`enterTouchDelay={0}`）。

> 範囲の端や、海などの標高データの無い場所から、外へ流れ出た水の量です。下水道・地面への浸み込み・蒸発は考えていません。

### 4.2 水深の凡例

`WaterLegend` の下に 1 行を足す。

> 1 cm 未満の薄い水は表示しません（領域内の水量には含みます）。

### 4.3 注意事項

`strings.disclaimer.lines` の 3 行目の後に 1 行を足す（R07-3）。

> 範囲の端や標高データの無い場所に達した水は、範囲の外へ流れ出たものとして扱います。

## 5. 流出しているセルの表示

### 5.1 判定

仮想セル（グリッドの外・無効セル）は、元のセルと同じ標高で水深 0 として扱われる（spec 03 §3.3）。そのため、「グリッドの端にあるか、無効セルに接している有効セル」のうち水深が θ を超えるものは、その step に必ず外へ流している。

これをエンジンの外で求める。

- 地形を読み込んだとき、メインスレッドで `outflowBoundaryMask: Uint8Array` を 1 回だけ作る。有効セルのうち、8 近傍にグリッドの外か無効セルを含むものが 1 になる。`validMask` から作れる。
- 描画のたびに、このマスクが 1 で、水深が表示の閾値（`OUTFLOW_VISIBLE_M`、R07-1）以上のセルを「流出中」とする。

ソルバーの計算のループには手を入れない。Worker とのメッセージも変えない。水深のバッファは既にメインに届いている。

### 5.2 描き方

範囲と同じ大きさの canvas ソースを 1 つ足す（`water-outflow`）。流出中のセルを赤紫（例: #c2185b、不透明度 0.9）で塗り、それ以外は透明にする。

- 水の canvas とは別のソースにする。3D の間は水の canvas を隠すが（spec 05 §3.6）、流出の層は 3D でも地形に貼って見せるためである（R07-2）。
- 再描画は水の描画と同じ rAF で行い、転送は `uploadCanvasSource` を使う（spec 06 §5.2）。マスクが 1 のセルだけを走査する（端の 1 周と無効セルの縁だけなので、1000 m でも数千セル）。前回塗ったセルの一覧を持ち、そこだけ消す。
- レイヤーの順は、`OVERLAY_LAYER_ORDER`（`src/map/layerIds.ts:23-33`）の `VIEW3D_LAYER_IDS.water` の直後、`terrain-outline` の前に足す。水の上、範囲の枠・矢印・○ の下になる。ID は `WATER_LAYER_IDS.outflow = 'water-outflow'` とする。
- ベースマップの切り替えの後の足し直し（`restore()`）と、地点の変更での消去（`clear()`）は、水の層と同じ扱いにする。

### 5.3 切り替え

`DisplaySettings` に「流出しているセル」のスイッチを足す。既定はオンとする。凡例は `MarkerLegend` の隣に「■ 範囲の外へ流出中」を足す。

設定は `persistedSettings.display.showOutflowCells: boolean` として保存する（tech-spec §8.3 に追記）。

- 今の `parsePersistedSettings`（`src/state/persistedSettings.ts:95-135`）は、項目が 1 つでも欠けると保存値全体を捨てる（`null`）。そのまま項目を足すと、v0.2.0 の利用者は注意事項の了解（`disclaimerAcknowledgedAt`）を含めて設定をすべて失う。
- そこで `showOutflowCells` だけは、欠けていれば既定の `true` で補う。型が違えば、これまでどおり全体を捨てる。`schemaVersion` は 1 のままにする（足すのは任意の項目で、形は変わらないため）。
- このことをユニットテストで確かめる（v0.2.0 の保存値がそのまま読めること）。

## 6. 性能

- 5.1 のマスクは、地形の読み込みのときに 1 回、O(N²) で作る。1000 m（約 1031²）でも数 ms と見込む。
- 5.2 の描画は、マスクのセル数に比例する。1000 m の最悪は、端の 1 周（約 4,100）と無効セルの縁である。
- canvas の転送は、水の canvas と同じ大きさのものがもう 1 つ増える。06 の fps probe（500 m・1000 m、2D と 3D）で、変更前と差が 0.5 fps 以内であることを確かめる。超えたら、転送を流出セルが変わった描画だけに絞る。
- 初回の読み込みの予算（initial 500 KB）を超えないこと。

## 7. テスト

### 7.1 ユニット

- `reduceClick`: `marker-click` で `kind: 'marker'` になる。`close` で閉じる。`confirm` では何もしない。
- `markerFeatures`: あふれ出し点に `depressionId` が付く。
- `outflowBoundaryMask`: 端、内側の無効セルの周り、無効セルそのもの（0）、全部有効の内側（0）。
- 流出の塗り分け: 閾値の境目、マスク外のセルは塗らない、前回の分を消す。
- `MarkerInfoPopover`: 2 種類の文言と数値。
- `StatisticsPanel`: ツールチップの文言。`WaterLegend`: 注記。`MarkerLegend`。

### 7.2 E2E（ポート 4173、フォアグラウンド）

- 地点を選び、最低点の ○ をクリックすると、説明と標高が出る。あふれ出し点でも同じ（fixture に有意な窪地を含む地点を使う）。
- ○ ではない場所のクリックは、今までどおりセル情報を開く。
- 3D に切り替えた後、○ のクリックで説明が開く。
- 範囲の端の近くに雨を置いて再生すると、`water-outflow` 層に色の付いた画素が出る。スイッチを切ると消える。
- ツールチップが開き、文言が出る。

### 7.3 手動確認

- スマートフォンの幅で、○ をタップして説明が開くこと。

## 9. 裁定が必要な論点

| ID | 論点 | 推奨 |
|---|---|---|
| R07-1 | 流出中として塗る水深の閾値 | **1 mm**。θ（1e-5 m）にすると、ごく薄い膜でも端の 1 周がすべて塗られ、どこから多く抜けているかが分からない。描画の 1 cm では、薄く抜けていく様子が見えない |
| R07-2 | 流出の層を 3D でも出すか | **出す**。3D がデモの主な見せ方なので。canvas の raster は 3D の地形に貼られる |
| R07-3 | 注意事項に流出の 1 行を足すか | **足す**。免責の範囲の話なので |
| R07-4 | 最低点とあふれ出し点が重なったときの優先 | **最低点**。1 セルの話で、最低点の方が説明が短い |

## 10. 後続への引き継ぎ

- 08（物理時間）では、流出の量を「毎時 m³」でも出せるようになる。この spec のツールチップの文を 08 で見直す。
- 簡易の排水の項を足すときは、流出と区別して統計に出すこと（「排水量」）。
