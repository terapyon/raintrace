## 1. 問い

tech-spec §5.5 で未決とした「地形と水面をどう描き分けるか」に答える。合わせて、Three.js が本当に必要かを確かめる（RS-2）。

### 合格基準（tech-spec §5.5）

1. 垂直強調 1x〜10x のすべてで、水深 1cm 以上の水面が地形に沈まず、ちらつかない
2. 垂直強調を、地形と水面に同じ倍率で適用できる（base-spec §29）
3. 水深を毎フレーム更新しながら地図を操作しても、60fps を維持できる（tech-spec §14.1）

## 2. 候補

| 候補 | 地形 | 水面 |
|---|---|---|
| A | MapLibre のネイティブ 3D terrain。`addProtocol` で GSI の標高 PNG を Terrarium 形式に変換する | Custom Layer 内の Three.js。高さはシミュレーションのグリッドの標高から |
| A' | A と同じ | A と同じだが、水面の高さを `queryTerrainElevation` で MapLibre の地形に合わせる |
| B | 範囲の中は Custom Layer 内の Three.js で地形メッシュを描き、ベースマップをテクスチャとして貼る。範囲の外は MapLibre の平面の地図 | 地形と同じグリッドから |
| B-raw | B を Three.js を使わずに生の WebGL2 で書く（RS-2） | 同上 |

## 3. 方法

- 使い捨てのブランチ `spike/3d-rendering` で行い、`main` にはマージしない
- 入力のグリッド: 02 が済んでいれば実データ。まだなら DEM1A の実タイル（02 のテスト用フィクスチャ）から組み立てたもの
- 入力の水深: 合成した固定の場（すり鉢に水深 5cm・50cm・2m の池、斜面に 1cm の薄い膜）と、毎フレーム値を変える場（1MB の転送とアップロードの負荷を見るため）
- 候補ごとに次を記録する

| 観点 | 方法 |
|---|---|
| 沈み込みとちらつき | 垂直強調 1・2・5・10x × pitch 0・45・60・85° × ズーム 15〜18 の組み合わせでスクリーンショットを撮り、並べて比べる |
| 倍率の一致 | 地形と水面に同じ倍率を掛けられるか、掛けたときにずれが出ないか |
| 速度 | 開発機で、水深を毎フレーム更新しながら地図を動かしたときの fps。可能ならもう1台の性能の低い機器でも |
| バンドル | Three.js を使う場合と使わない場合の gzip 後のサイズの差 |
| 複雑さ | コードの行数、回避策の数 |
| 継ぎ目 | B の場合、範囲の境界に見た目の段差がどの程度出るか |
| z-fighting | 水面と地形が 1cm 差で重なる箇所で、深度バッファの精度が足りるか。対策の候補（水面を後に描いて polygonOffset を付ける。方式 B なら地形と水面で頂点を共有し、描画順で解決する）も試す |
| Custom Layer の API（方式 A） | 使う版の MapLibre の Custom Layer が受け取る行列と引数の形。`setTerrain` を併用したとき、その行列に地形の高さが反映されるか |
