# Spec 02: DEM グリッドと 2D 表示

- Status: 確定（2026-09-10 裁定）
- 日付: 2026-09-10
- 対応: base-spec §55 Phase 1（R02-1）、§56、§57 #2・#3
- 依存: 01
- 後続: 03（越流イベントと検証の基準に地形解析を使う）、04、S（実データ）

---

## 1. 目的

地図で選んだ地点の周囲の DEM を取得し、シミュレーション用のグリッドを組み立て、地形の性質（最低点・流向・窪地・spill point）を 2D で確かめられるようにする。

base-spec §56 は、最初に確認すべきことを「3D 描画ではなく、DEM から本当に期待した窪地・流路が得られるか」としている。この spec はそれを 3D より先に検証するためのものである。

## 2. スコープ

### 含む

- 地点の選択（クリック）と、範囲（500m 四方）の表示。URL との同期（`lat`・`lon`・`z`・`size`）
- DEM の取得（Worker 内）、選択（3 段）、デコード、グリッドの組み立て
- 地形解析: D8 の流向、窪地（Priority-Flood）、spill point、最低点
- 2D 表示: 標高の色分け、最低点、地形の流向の矢印、窪地（満水時の深さ）、spill point
- パネル: 地点、DEM 情報（base-spec §40）、標高の範囲、カーソル位置の標高、表示の切り替え
- 読み込み中の表示とエラー表示
- Zustand の導入（この spec で最初に必要になる）

### 含まない

- 水・降雨・再生（03・04）、セル情報のポップオーバー（04）、範囲の大きさを選ぶ UI（04、R02-4）、設定の永続化（04）、3D（S・05）

## 3. 範囲とグリッド

tech-spec §7.6 の定義に従う。

- クリックした地点を中心 (`lat`, `lon`) とする
- 選んだ段の DEM のズーム `z` で、中心のグローバルピクセル座標 `pc` を求める
- 一辺のセル数 `N = ceil(sizeM / cellSizeM)`、`cellSizeM = 地上解像度(lat, z)`
- グリッドの原点（北西端）は `origin = round(pc − N/2)`（ピクセル単位）。グリッドはピクセルの格子に揃い、リサンプリングしない。範囲の中心は、クリックした地点から半セル以内に来る（2026-09-10、実装計画のレビューで floor から改めた。floor では範囲の中心が最大 1 セルずれ、この主張と両立しない）
- 範囲の四隅の緯度経度は、`origin` と `origin + N` のピクセル座標から逆算する
- 04 で降雨中心をエンジンに渡すときの座標（グリッドの北西端からの m）は、`(pc − origin) × cellSizeM` で求まる

## 4. DEM の取得と選択

### 4.1 段（R02-2）

| 段 | DEM | z | タイルのパス |
|---|---|---|---|
| 1 | DEM1A | 17 | `dem1a_png` |
| 2 | DEM5（タイルごとに 5A → 5B → 5C の順で合成） | 15 | `dem5a_png`、`dem5b_png`、`dem5c_png` |
| 3 | DEM10B | 14 | `dem_png` |

段 2 では、同じズームの 5A・5B・5C をタイル単位で混ぜてよい。解像度が同じなので、グリッドに解像度の混在は生じない。

### 4.2 手順

```
for 段 in [1, 2, 3]:
  範囲にかかるタイル（段のズーム）をすべて取得する
    段 2 は、タイルごとに 5A → 5B → 5C の順に、200 が返るまで試す
  404 のタイルが無い → この段を採用
  404 のタイルがある → 各 404 タイルを海域判定する
    すべて海域     → そのタイルを全画素無効値として扱い、この段を採用
    陸域が1つでも → 次の段へ
段 3 で 404 のタイル → 海域・国外として全画素無効値
範囲の全画素が無効値 → 「この地域には標高データがありません」
```

**海域判定**: 404 になったタイルの範囲に当たる `dem_png`（z14）の画素を調べる。すべて無効値なら海域とする。`dem_png` 自体が 404 の場合も海域（国外を含む）とみなす。`dem_png` のタイルは判定のたびに取り直さず、1 回の読み込みの中で使い回す。

- 調べる `dem_png` の画素の窓は、z17 のタイル1枚につき 32 × 32 画素、z15 のタイル1枚につき 128 × 128 画素（ズームの差がそれぞれ 3 と 1 なので、256 ÷ 2³ と 256 ÷ 2）
- 「すべて無効値」は厳密に判定する。1 画素でも有効な標高があれば陸域とする
- `dem_png` の取得がネットワークエラーの場合は海域とみなさず、通常の再試行とエラーの扱い（§4.3）に乗せる。海域とみなすのは `dem_png` が 404 の場合だけとする

**DEM1A のタイル内の無効画素は、下位の DEM で埋めない。** 無効セルとして扱い（tech-spec §7.2）、範囲内の無効セルの割合をパネルに出す。

### 4.3 取得（Worker 内、`workers/demLoader.ts`）

- `fetch(url)`（CORS モード）→ 200 なら `blob()` → `createImageBitmap(blob, { premultiplyAlpha: 'none', colorSpaceConversion: 'none' })` → `OffscreenCanvas(256, 256)` の `getContext('2d', { willReadFrequently: true })` に描いて `getImageData()` → RGBA を `GsiDemDecoder` へ
- 404 は「タイルなし」として扱う。それ以外の HTTP エラーとネットワークエラーは、0.5 秒・1 秒・2 秒の間隔で最大 3 回再試行し、それでも失敗したらエラーにする
- 同時に取得するのは最大 6 件
- 新しい地点がクリックされたら、`AbortController` で取得中のものを取り消す。古い読み込みの結果はリクエスト ID で見分けて捨てる
- キャッシュは HTTP キャッシュのみ（tech-spec §8.4）
- OffscreenCanvas は必須とし、メインスレッドでデコードする経路は作らない（R02-5）

### 4.4 デコードとグリッドの組み立て（`src/dem/`、純粋関数）

- `GsiDemDecoder`: RGBA のバイト列から、標高の `Float32Array` と有効セルマスクの `Uint8Array` を作る（tech-spec §7.2 の式）
- `DemGrid`: 取得したタイルを結合し、範囲を切り出す。結果は `{ elevation, validMask, meta: { width, height, cellSizeM }, geo: { z, origin, 使った DEM の内訳 } }`
- Worker はグリッドを保持し、標高のコピー・マスク・メタ情報・地形解析の結果をメインスレッドへ送る（tech-spec §5.4）

## 5. 地形解析（`src/simulation/terrain/`、R02-6）

入力は `(elevation, validMask, width, height, cellSizeM)` で、すべて純粋関数とする。Worker 内で、グリッドの組み立ての直後に実行する。

| 関数 | 出力 | 方法 |
|---|---|---|
| `lowestCell` | 標高が最小の有効セルの番号 | 全走査 |
| `d8FlowDirection` | `Uint8Array`（0 = 下り先なし、1〜8 = 方向） | 勾配 `ΔZ / 距離` が最大の近傍（対角の距離は `√2 × cellSizeM`）。同じ勾配なら固定の近傍順で決める。グリッドの外は近傍に含めない |
| `analyzeDepressions` | 満水時の水面 `F`、窪地のラベル（`Int32Array`）、窪地ごとの要約 | Priority-Flood（Barnes ほか, 2014）。グリッドの端のセルと無効セルに隣接するセルを起点にする |

窪地ごとの要約は、最大深さ（`F − Z` の最大）、面積、容量（`Σ(F − Z) × セル面積`）、spill 標高（その窪地の `F`）、最低点のセル、spill point のセルとする。

標準の Priority-Flood は spill point を返さないので、フラッドの途中で記録する。優先度付きキューから取り出したセル c の近傍 n が `Z_n < F_c` のとき、n は窪地の中にあり、水位 `F_c` まで引き上げられる。その窪地のセルを**最初に**引き上げたときの c が spill point（そこから水が溢れ出るセル）である。キューは低い順に取り出すので、最初の引き上げは最も低い縁から起きる。

- 取り出したセル c 自身がすでに引き上げ済み（`F_c > Z_c`）の場合は、c が属する窪地に隣のセルを併合するだけで、新しい spill point にはならない。入れ子の窪地が1つにまとめられる（03 §4.2）のはこの分岐による
- 同じ標高の縁が複数あると、どれが先に取り出されるかで spill point が変わる。優先度付きキューは同じ値のときの順序を保証しないので、挿入順を第2キーにして決定的にする

- グリッドの端と無効セルを起点にするのは、03 の境界の扱い（R03-2: 境界の外や無効セルへ出た水は流出する）と揃えるためである。これにより、03 の動的モデルで水を十分に入れて平衡させた結果は、ここで求める `F` と一致するはずで、03 の検証の基準になる
- 表示と越流イベント（R03-6）の対象は、最大深さ 5cm 以上かつ面積 10m² 以上の窪地に限る（R02-3）。DEM の細かな凹凸でできる微小な窪地を除くためである
- 計算量は Priority-Flood が O(n log n) で、512 × 512 セルでも数十 ms の見込み

## 6. 2D 表示

### 6.1 地図のレイヤー

| レイヤー | 方式 | 内容 |
|---|---|---|
| 標高 | `canvas` ソース（範囲の四隅に合わせる） | 範囲内の最低〜最高を色覚特性に配慮した連続色で表示。凡例に最低・最高（0.01m 単位） |
| 窪地 | `canvas` ソース | 満水時の深さ（`F − Z`）を 5cm 刻みで表示。04 で表示する水深とは別の配色にして、「実際の水」と取り違えないようにする |
| 地形の流向 | GeoJSON の点と symbol レイヤー | 5・10・20m 間隔で間引いた矢印（base-spec §32）。既定は 10m。下り先のあるセルのみ |
| 最低点・spill point | circle または symbol レイヤー | 最低点は1つ、spill point は表示対象の窪地ごと |
| 範囲の枠と中心 | line レイヤーと MapLibre の Marker | |

canvas への着色はメインスレッドで行う（262,144 画素で数 ms の見込み）。内容が変わらないので、`canvas` ソースは `animate: false` とする（04 の水深の表示は `animate: true`）。

### 6.2 パネル

MUI の `Drawer`（`md` 以上は右、それ未満は下。tech-spec §9.3）に次を置く。

- 地点（緯度経度、小数 6 桁）と範囲（500m）
- `DemInfoBadge`: 使った DEM（例: 「DEM5A（一部 DEM5B）」）、セルの大きさ（例: 「約 0.98m」）、無効セルの割合。DEM1A でない場合は base-spec §40 の注意文
- 標高: 最低・最高（0.01m 単位）
- カーソル位置の標高（0.01m 単位。範囲外なら「範囲外」、無効セルなら「データなし」）。マウスの移動に合わせて更新するが、ストアへの反映は描画フレームごとに1回に間引く
- 窪地: 表示対象の件数と、容量が最大の窪地の最大深さ・容量・spill 標高
- 表示の切り替え: 標高・窪地・地形の流向の各スイッチ、矢印の間隔（5・10・20m）

### 6.3 状態の置き場所

- Zustand のストア: 選んだ地点、読み込みの状態と進捗、DEM 情報、表示の切り替え、カーソル位置の標高
- 標高のコピーと地形解析の配列は `bridge/SimulationClient` が持ち、React には載せない（tech-spec §2 原則2）

## 7. エラー処理

| 事象 | 挙動 |
|---|---|
| 範囲の全画素が無効値（海上・国外） | 「この地域には標高データがありません」を表示し、範囲を消す |
| 再試行しても取得に失敗 | エラーを表示し、「再試行」ボタンを出す |
| 読み込み中に別の地点をクリック | 取得中のものを取り消し、新しい地点で始め直す |
| Worker の異常終了 | 読み込み中なら失敗（'worker'）として表示し、次の要求で起動し直す。待機中・表示中に落ちた場合は、メインの複製で表示を続け、次のクリックで起動し直す |
| 対応範囲の外 | 取得せずに『この地点は対応範囲（日本国内）の外です』を出す（info、再試行なし）。対応範囲は緯度 20〜46°・経度 122〜154°（`src/dem/serviceArea.ts`） |

## 8. テスト

### 8.1 ユニット

| 対象 | 内容 |
|---|---|
| `GsiDemDecoder` | 既知の RGB: (0,0,0)→0m、(0,0,1)→0.01m、(0,1,0)→2.56m、(1,0,0)→655.36m、(128,0,0)→無効、(255,255,255)→−0.01m。テスト用のエンコーダでランダムな値を往復させる |
| `tileMath` と範囲 | `origin` と `N` の計算、範囲の中心がクリック地点から半セル以内に来ること、範囲にかかるタイルの列挙 |
| `DemGrid` | 2 × 2 の合成タイルを結合し、継ぎ目の画素と番号が正しいこと |
| 段の選択 | 取得関数を差し替えて: すべて 200／海域の 404／陸域の 404 で次の段へ／段 2 の 5A と 5B の合成／ネットワークエラーの再試行と失敗／取り消し |
| 地形解析 | 平面（窪地なし）、一様な斜面（すべて下り方向）、単一の窪地（spill 標高と容量が理論値どおり）、峠でつながった2つの窪地（spill 標高が峠の高さ、spill point の位置）、端と無効セルの起点、同じ勾配での方向の決め方と、同じ標高の縁が複数あるときの spill point の位置が決定的であること |

カバレッジは `src/dem/` 85%、`src/simulation/` 90%（tech-spec §11.5）。

### 8.2 実タイルでの回帰（tech-spec §5.4 の「実タイル 1 枚の既知の画素」）

- 地理院の DEM1A タイル 1 枚を `tests/fixtures/` に置く。README に、出典、タイルの URL、取得日、期待値を求めた手段（使ったツールやスクリプト）を記し、再現できるようにする。地理院のコンテンツは出典の明示で利用できる
- 期待値（最低・最高の標高）は、ブラウザとは別の実装（Python など）で一度だけデコードして求め、定数としてテストにコミットする。求めた手順を README に記す。PNG のデコーダをリポジトリに持たずに済む
- E2E で、すべての DEM リクエストにこのタイルを返す。範囲は 2 タイル幅以上にわたるので、タイルのすべての画素位置が範囲に含まれ、パネルの最低・最高は期待値と一致するはずである。これで、ブラウザ側の `createImageBitmap` の経路が画素値を変えていないことを確かめられる

### 8.3 E2E

1. クリックすると、中心のマーカーと範囲の枠が出る
2. DEM 情報バッジに「DEM1A」と出る
3. 最低・最高の標高が §8.2 の期待値と一致する（`@webkit` タグを付け、WebKit でも実行する。R01-4）
4. DEM1A を 404 にし、`dem_png` を陸域の値で返すと、バッジが「DEM5A」になる
5. 一部の DEM1A タイルを 404 にし、`dem_png` を無効値で返すと、「DEM1A」のまま無効セルの割合が 0 より大きくなる
6. すべて 404 にすると「この地域には標高データがありません」と出る
7. 表示のスイッチを切り替えてもエラーが出ない
8. クリックすると URL に `lat`・`lon` が入り、再読み込みすると同じ地点が選ばれる
9. Worker 内の fetch も `browserContext.route()` で差し替えられている（差し替えた件数を確かめる）

### 8.4 手動確認（R02-7）

地点は、都市部を中心に実装役が選ぶ（R02-7 の裁定）。平坦な市街地・谷のある市街地・沿岸の市街地のように、性格の異なる3か所とする。

3 地点で、窪地と流向が航空写真や地形から見て妥当かを確かめ、スクリーンショットと所見を PR に記録する。

## 10. 裁定が必要な論点

> 裁定（2026-09-10）: R02-1 は承認（Phase 1 は 2D まで）。R02-7 は変更（都市部を中心に実装役が選ぶ）。その他は推奨どおり承認。本文は裁定を反映済み。

| ID | 論点 | 推奨 | 理由 |
|---|---|---|---|
| R02-1 | Phase 1 の範囲 | 2D 表示までとし、3D terrain は S と 05 に移す | base-spec §56 が「最初は 3D 描画ではない」としていることに合わせる。3D は tech-spec §5.5 で未決の最大リスクなので、Phase 1 の完了条件と切り離す。base-spec §55 との差異になる |
| R02-2 | DEM の選び方 | §4.1・§4.2 のとおり | 解像度の混在を作らない（tech-spec §20 #4）。一方で、沿岸では海域の DEM1A タイルも 404 になるため、単純に「1 枚でも 404 なら段を下げる」と海に面した地域が軒並み DEM5 に落ちる。海域判定でそれを避ける。DEM1A のタイル内の無効画素を下位の DEM で埋めないのは、画素単位で解像度が混ざるのを避けるため。tech-spec §7.4 を改訂する（T4） |
| R02-3 | 窪地の表示閾値 | 最大深さ 5cm 以上、かつ面積 10m² 以上 | 5cm は水深の表示の刻み（tech-spec §6.6）に合わせた。面積を m² で決めるのは、DEM の解像度によらず同じ基準にするため |
| R02-4 | 範囲の大きさ | 02 では 500m 固定。選択 UI は 04 | base-spec §8 が「初期リリースでは 500m 固定でもよい」としている。グリッドの計算は大きさによらない作りにしておく |
| R02-5 | OffscreenCanvas | 必須とし、フォールバック経路を作らない | 対象ブラウザ（base-spec §58 の最新版）はすべて、Worker 内の OffscreenCanvas と 2D コンテキストに対応している。使われない経路を保守しない。tech-spec §7.5・§15.2 を改訂する（T5） |
| R02-6 | 地形解析の置き場所 | `src/simulation/terrain/` | DOM に依存しない純粋な計算であり、03 のエンジンと検証でも使う。tech-spec §4.1 に追加する（T1） |
| R02-7 | 手動確認の 3 地点 | ユーザーが指定する。指定がなければ、平坦な市街地・谷のある斜面・沿岸を1か所ずつ実装役が選ぶ | 06 のベンチマークと同じ地点にする（R06-1） |

## 11. 後続への引き継ぎ

- 03: 窪地の要約（最低点のセルと spill 標高）を越流イベントに、満水時の水面 `F` を平衡状態の検証の基準に使う
- 04: `(pc − origin) × cellSizeM` による降雨中心の座標変換、範囲に合わせた `canvas` ソースの仕組み（水深の表示に流用する）
- S: 実データのグリッド
